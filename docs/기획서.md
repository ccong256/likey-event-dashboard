# LIKEY 이벤트 대시보드 기획서

## 1. 서비스 개요

### 1.1 문제 정의
- 현재: CSV 다운로드 → 스프레드시트 전처리 → 루커스튜디오 시각화
- 매 이벤트마다 반복되는 수작업, 실시간 모니터링 어려움

### 1.2 솔루션
CSV 업로드 + AI 분석으로 대시보드와 인사이트가 자동 생성되는 사내 서비스

### 1.3 사용자
- 비즈팀 담당자, 상급자, 마케팅팀, 기획팀
- 인증: 공유 비밀번호로 접근 제한

## 2. MVP 범위

## 3. 선물 이벤트 이해

### 3.1 선물 기능
- 앱에 항상 존재하는 기본 기능
- 팬이 크리에이터에게 선물을 보냄

### 3.2 선물 이벤트
- 특정 테마 선물 카테고리를 만들어 **선물할 명분** 제공
  - 팬: "발렌타인데이니까 선물해야지"
  - 크리에이터: "이벤트니까 선물 달라고 해도 돼"
- **목표: 매출 상승**

### 3.3 성과 측정
- 이벤트 테마 선물을 얼마나 받았는지 → 크리에이터 랭킹
- 모든 KR 크리에이터가 대상 (참여 개념 없음)
- 선물을 받으면 자동 집계

## 4. 데이터 구조

### 4.1 선물 CSV (gift-stats)
```
Uid, NickName, username, country,
골드 수량, 선물 수량, 선물을 보낸 유저 수, 선물 보낸 유저들 정보
```

### 4.2 데이터 업로드 방식
- **이벤트 기간 데이터**: 이벤트 기간 동안의 CSV
- **직전 기간 데이터**: 이벤트와 동일 일수의 직전 기간 CSV
- 예: 7일 이벤트 → 이벤트 기간 CSV + 직전 7일 CSV

### 4.3 참고
- 선물 카테고리(키값)는 어드민에서 이미 필터링해서 CSV 추출
- 대시보드에서는 받은 데이터 그대로 사용

## 5. 핵심 기능

### 5.1 이벤트 관리
- 이벤트 등록 (이름, 기간, 참여 국가)
- 이벤트 목록 및 상태 관리

### 5.2 데이터 업로드
- CSV 파일 업로드 (이벤트 기간 + 직전 기간)
- 데이터 검증 및 미리보기

### 5.3 모니터링 대시보드
**목적**: 비즈팀 담당자/상급자가 한눈에 현황 파악

| 구성요소 | 설명 |
|---------|------|
| KPI 카드 | 총 골드, 선물 수량, 참여 유저 수 |
| 랭킹 테이블 | 골드 TOP / 선물 수량 TOP |
| 필터 | 기간 설정 |

### 5.4 성과 분석

#### 매출 분석
| 분석 항목 | 내용 |
|----------|------|
| 전체 매출 상승률 | 이벤트 기간 총 매출 vs 직전 기간 총 매출 |
| 크리에이터별 상승률 | 각 크리에이터의 이벤트 vs 직전 기간 비교 |

#### AI 기능 (OpenAI 연동)
| 기능 | 설명 |
|-----|------|
| 자동 인사이트 | 데이터 업로드 시 핵심 인사이트 자동 생성 |
| 자연어 질문 | "크리에이터별 매출 상승률 보여줘" → 차트 생성 |

### 5.5 이벤트 비교
- 같은 유형 이벤트끼리 비교 (예: 빼빼로데이 vs 발렌타인데이)
- 기간이 다를 경우 **일평균으로 정규화**해서 비교

| 이벤트 | 기간 | 총 매출 | 일평균 매출 |
|-------|-----|--------|-----------|
| 빼빼로데이 | 7일 | 1.5억 | 2,140만 |
| 발렌타인데이 | 14일 | 3.5억 | 2,500만 |

## 8. DB 스키마 (Supabase)

```sql
-- 이벤트 정보
CREATE TABLE events (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  name TEXT NOT NULL,
  type TEXT NOT NULL DEFAULT 'donation',
  description TEXT,
  start_date DATE NOT NULL,
  end_date DATE NOT NULL,
  target_countries TEXT[] DEFAULT '{KR}',
  status TEXT DEFAULT 'active' CHECK (status IN ('active', 'ended')),
  created_at TIMESTAMPTZ DEFAULT NOW()
);

-- 저장된 대시보드
CREATE TABLE dashboards (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  event_id UUID REFERENCES events(id) ON DELETE CASCADE,
  name TEXT,                              -- 대시보드 이름 (선택)
  dashboard_type TEXT NOT NULL DEFAULT 'monitoring' CHECK (dashboard_type IN ('monitoring', 'analysis')),
  data_start_date DATE NOT NULL,          -- 데이터 시작일
  data_end_date DATE NOT NULL,            -- 데이터 종료일
  summary JSONB NOT NULL,                 -- 요약 데이터 (총 매출, 선물 수, 참여자 수 등)
  ranking JSONB NOT NULL,                 -- 크리에이터 랭킹 데이터
  before_summary JSONB,                   -- 직전 기간 요약 (성과분석용)
  before_ranking JSONB,                   -- 직전 기간 랭킹 (성과분석용)
  created_at TIMESTAMPTZ DEFAULT NOW()
);
```

### summary JSONB 구조
```json
{
  "totalGold": 1508029,
  "totalRevenue": 150802900,
  "totalGiftCount": 4471,
  "totalSenderCount": 1427,
  "creatorCount": 40
}
```

### ranking JSONB 구조
```json
[
  {
    "rank": 1,
    "uid": "123",
    "nickname": "유저1",
    "username": "user1",
    "gold": 233690,
    "revenue": 23369000,
    "giftCount": 443,
    "senderCount": 49
  },
  ...
]
```
